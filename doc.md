📋 校园互助平台（Campus Helper）完整项目分析

一、项目概览

这是一个校园互助平台，允许学生/教师发布任务、接单、实时聊天、互评，管理员可管理分类和用户。前后端分离架构。

设计亮点：
- 任务支持双方确认完成机制（publisher_confirmed + acceptor_confirmed）

- 唯一约束 uk_task_reviewer 防止重复评价

七、⚠️ 问题与风险

🔴 严重（CRITICAL）

1. 硬编码数据库密码
   - backend/seed.js:12 和 database/seed.js:12 直接写死密码 huang20050711
   - 应改用环境变量
2. CORS 完全开放
   - app.js:20 设置 origin: '*'，任何域名都可以调用 API
   - 生产环境必须限制
3. 无频率限制
   - 登录接口无 rate limiting，可被暴力破解
   - 所有 API 无请求频率限制

🟡 高级（HIGH）

4. SQL 注入风险（潜在）
   - task.js:53 的 count SQL 使用字符串替换 sql.replace(/SELECT .+ FROM/, ...)，虽然参数化查询在前面，但这种模式脆弱
   - task.js:112 动态字段名 ${field} 拼接到 SQL 中（虽然是内部枚举，但不够安全）
5. Socket.io 消息无权限校验
   - socket.js 中 send_message 只检查是否被封禁，未验证发送者是否为任务参与者
6. 头像上传路径硬编码
   - Profile.vue:91 和 TaskDetail.vue:15-19 硬编码 http://localhost:3000
   - 应使用环境变量或相对路径
7. JWT 密钥默认值弱
   - config/index.js:16 默认值 'default_secret_change_me'，若未配置 .env 则极不安全

🟠 中级（MEDIUM）

8. 无测试
   - 后端 package.json 的 test 脚本是 echo "Error: no test specified"
   - 零测试覆盖率
9. seed.js 重复
   - database/seed.js 和 backend/seed.js 功能重复，且使用不同数据结构（旧版用字符串分类，新版用 category_id）
10. 分页参数未校验上限
    - limit 参数无最大值限制，恶意请求 limit=999999 可能导致性能问题
11. 确认完成的竞态条件
    - task.js:99-122 的 confirmCompletion 方法先读后写，存在 TOCTOU 竞态
12. 前端错误处理不统一
    - 部分 catch 块静默忽略错误（如 TaskDetail.vue:146），部分显示错误消息

🟢 低级（LOW）

13. 无日志系统
    - 仅使用 console.error，生产环境应使用 winston/pino
14. 无 API 文档
    - 缺少 Swagger/OpenAPI 文档
15. .idea/ 目录被提交
    - .gitignore 有 .idea/ 但目录仍存在（可能已跟踪）
16. 无 Docker/部署配置
    - 缺少 Dockerfile、docker-compose 等部署文件

八、架构评价

✅ 优点

- 分层清晰：routes → controllers → models，职责明确
- 参数校验完善：使用 express-validator + validate 中间件
- JWT + 中间件：鉴权/权限分离，复用性好
- 双方确认机制：任务完成需要双方确认，设计合理
- 信用分系统：评价影响信用分，激励良好行为
- 实时聊天：Socket.io 集成，用户体验好

❌ 不足

- 无测试、无 CI/CD、无日志系统
- 安全配置不完善（CORS、rate limit、硬编码密码）
- 部分代码存在安全隐患（SQL 拼接、Socket 权限）
- 无 Docker 化部署方案
- 无 API 文档
